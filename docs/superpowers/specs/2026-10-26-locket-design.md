# Locket 设计文档 v3

> 一个多用户照片展示网站：3D 旋转照片墙 + 自定义分类相册 + 手机直传 + 一键导出朋友圈素材。
> 用户注册后拥有自己的相册（可自建分类、自定义命名），互相关注授权后看对方的墙（可配置协作上传）。
> 整理日期：2026-10-26（v2→v3：增加多视图/灯箱/心形模式/年度回顾/PWA/相册分类/协作上传）。状态：已批准（v2 四项决定均认可，v3 新增项为用户本轮拍板）。

## 1. 意图与动机

普通相册/网盘缺少「心意感」。Locket（吊坠盒）把照片放进 3D 旋转墙——像把照片装进首饰盒。
首版场景：情侣各自注册，建自己的相册分类（旅行/日常/美食……），互相授权后看对方的墙、
把合影传到对方开了协作的相册里；遇到好看的画面一键导出 PNG，年底自动生成回顾海报发朋友圈。

**为什么做这个**：仪式感 + 实用（朋友圈素材）+ 练手极致前端动效。

## 2. 目标（首版必须做到）

1. **3D 旋转照片墙**：照片沿圆柱面排布，拖拽旋转（带惯性）、闲置自动慢转；手机触屏可玩。
2. **账户体系**：邮箱+密码注册登录；每人拥有自己的相册。
3. **自定义分类相册**：用户自建相册、自行输入命名；照片归属相册；相册可重命名/删除。
4. **多视图**：相册内 3D 墙 / 时间轴 / 瀑布流 三视图切换。
5. **灯箱**：点开照片看大图与日期；墙主可删除、设封面；协作上传者只能删自己的。
6. **互相关注/授权**：A 申请关注 B，B 同意后 A 可只读看 B 的相册；**协作上传为 per-相册开关**——开了之后授权对象也能往该相册传照片。
7. **照片管理**：删除；长按拖拽调整照片在墙内的顺序。
8. **导出画面**：当前墙画面一键导出 PNG（适合发朋友圈）。
9. **心形聚合模式**：照片从圆柱飞出、聚成旋转爱心后定格，专门用于导出分享。
10. **打包下载**：相册内全部照片打包 zip 下载（数据兜底）。
11. **年度回顾海报**：按年份自动生成拼贴海报（按月抽样 + 统计文案），导出即朋友圈素材。
12. **纪念日模块**：设置纪念日后首页显示累计天数（CountUp），纪念日当天自动飘粒子彩蛋。
13. **PWA**：可「添加到主屏幕」，全屏 App 体验。
14. **极致动效**：React Bits 组件做氛围（背景、入场、微交互），WebGL 背景懒加载 + 移动端降级。

## 3. 非目标（首版明确不做）

- 评论、点赞、访客统计
- 照片滤镜/编辑/裁剪（仅上传前压缩）
- 微信小程序、原生 App
- 相册级以外的细粒度权限（关注即整相册可见）
- 关注申请的消息通知（靠登录后红点）
- 视频/Live Photo

## 4. 反目标（即使技术上能跑，出现就算失败）

- **照片丢失**：存储可靠 + 打包下载兜底必须真能用。
- **越权**：绝不能看到/动到未授权用户的数据；RLS 兜死，不只靠前端隐藏。
- **手机卡顿发烫**：动效必须有移动端降级（`prefers-reduced-motion`、低端机降背景、同屏只放一个 WebGL 背景）。
- **国内打不开/传不动**：Netlify 免费托管国内访问一般——用户已知情并接受。

## 5. 约束

- **免费优先**：Netlify 免费静态托管 + Supabase 免费额度（Auth 5万MAU / Storage 1GB / DB 500MB）。
- **技术栈**：Vite + React + TypeScript + Tailwind CSS。
- **组件来源**：React Bits（shadcn 式源码组件，MIT + Commons Clause，个人项目免费可用）。
- **包管理**：npm（E 盘 exFAT 不支持符号链接，pnpm 会挂）。
- **网络**：GitHub 走 SSH；reactbits.dev 拉不动就官网手动复制组件源码。
- **MCP**：`.kimi-code/mcp.json` 已配 shadcn MCP；context7 查文档。
- **部署**：Netlify 手动部署（git 集成或 CLI 由实现时定）。

## 6. 架构

```
┌──────────────────────────────────────────────┐
│  Netlify（静态托管，手动部署；PWA Service Worker） │
│  ┌────────────────────────────────────────┐  │
│  │ React SPA (Vite + TS + Tailwind)        │  │
│  │  ├─ 登录/注册                            │  │
│  │  ├─ 我的相册列表（新建/重命名/删除）         │  │
│  │  ├─ 相册内：3D墙 / 时间轴 / 瀑布流        │  │
│  │  ├─ 灯箱 / 拖拽排序 / 删除                │  │
│  │  ├─ 心形聚合模式                         │  │
│  │  ├─ 导出 PNG / 打包下载 zip              │  │
│  │  ├─ 年度回顾海报生成器                    │  │
│  │  ├─ 关注/授权管理 + 协作上传              │  │
│  │  └─ React Bits 氛围组件（懒加载）         │  │
│  └────────────────────────────────────────┘  │
└──────┬───────────────────────┬───────────────┘
       │ 用户 JWT (Supabase Auth)│
       ▼                        ▼
  Supabase Auth             Supabase Postgres + Storage
  (邮箱+密码)               albums / photos / follows 表 + Storage 桶
```

### 数据模型（Supabase Postgres）

- `albums`：`id`, `owner_id`(→auth.users), `name`, `allow_collab_upload`(bool, 默认 false), `created_at`。
- `photos`：`id`, `album_id`(→albums), `uploader_id`(→auth.users), `storage_path`, `sort_order`, `created_at`。
- `follows`：`id`, `follower_id`, `followee_id`, `status`('pending'/'accepted'), `created_at`；
  唯一约束 `(follower_id, followee_id)`。

Storage 路径：`{album_owner_id}/{album_id}/{photo_id}.webp`（上传即压缩：长边 2048、WebP，原图不保留——已确认接受）。

### 权限（RLS 策略，兜死在数据库层）

- 可见性（单向）：A 申请关注 B，B 同意后，A 可**只读**看 B 的所有相册。
- `albums`：SELECT = 本人 + 对本人有 accepted 关注的人；INSERT/UPDATE/DELETE 仅本人（改协作开关也是本人）。
- `photos`：
  - SELECT = 相册可见者（同 albums 规则）。
  - INSERT = 相册 owner，或（相册 `allow_collab_upload` 且与 owner 存在 accepted 关注，任一方向）。
  - UPDATE/DELETE = 照片 uploader 本人，或相册 owner。
- `follows`：INSERT 任何登录用户；SELECT 仅涉及双方；UPDATE 仅 followee（同意/拒绝）；DELETE 双方。

### 3D 墙与导出

- 墙本体：CSS 3D transforms 圆柱排布 + pointer events 拖拽 + 惯性 + 自动旋转（不用 Three.js 做本体，WebGL 只给背景组件且懒加载）。
- 导出 PNG：`html-to-image` 截当前墙 DOM；若 `preserve-3d` 翻车，退化 canvas 按当前角度重绘（先 spike 验证）。
- 心形聚合：照片元素从圆柱位移动画（FLIP/JS 计算心形目标坐标）聚成旋转爱心；定格后可直接导出 PNG。属 P4 的 spike 项。
- 打包下载：前端流式打包 zip（jszip），逐张拉取带进度条。
- 年度回顾：前端按年筛选照片 → 按月桶抽样 → Canvas 拼贴网格 + 统计文案（当年张数、最常出现的月份）→ 导出 PNG。

## 7. 页面结构

1. **登录/注册页**：邮箱+密码。
2. **我的相册列表**：相册卡片网格（封面图 + 名称 + 张数），新建（弹窗输入名称）/重命名/删除；React Bits 卡片动效。
3. **相册页**：顶部切换 3D墙/时间轴/瀑布流；浮动 Dock：上传、导出 PNG、心形模式、打包下载、排序模式、协作开关（owner）、自动旋转开关；灯箱点开大图。
4. **关注页**：发起关注（输邮箱）、处理申请（同意/拒绝）、我正在看谁的相册。
5. **TA 的相册**：只读视图（协作开关开着则可上传）；同样三视图可玩，Dock 按权限裁剪。
6. **年度回顾**：选年份 → 生成海报 → 导出。

## 8. 阶段拆分

| 阶段 | 内容 | 验收 |
|---|---|---|
| P1 | 脚手架（Vite+React+TS+Tailwind+shadcn/react-bits registry）+ 3D 墙空转 + 假数据 + React Bits 背景 | 本地能拖能转 |
| P2 | Supabase 项目 + Auth + 相册 CRUD + 上传（压缩直传）/列表/删除 | 注册登录后手机能建相册、传照片 |
| P3 | 时间轴 + 瀑布流视图 + 灯箱 + 拖拽排序 | 三视图切换流畅，灯箱/排序可用 |
| P4 | 导出 PNG（先 spike 截图方案）+ 心形模式 spike + 打包下载 | 导出图可发朋友圈；zip 完整 |
| P5 | 关注/授权 + 协作上传（RLS 联调） | A 申请 B 同意，A 看 B 墙；协作开关生效 |
| P6 | 纪念日模块 + PWA + 移动端降级打磨 | 主屏幕可安装；弱动效模式生效 |
| P7 | 年度回顾海报 + Netlify 部署 + 生产配置（RLS 复查、额度/错误提示） | 公网全流程走通 |

## 9. 主要风险与对策

- **html-to-image / 心形模式对 CSS 3D 的兼容**：P4 先 spike，翻车退 canvas 重绘。
- **Netlify 国内访问**：用户已接受；后续可绑自定义域名。
- **免费额度**：压缩后约 300KB/张 ≈ 1GB/3000 张；页面做额度/错误提示。
- **Supabase 免费版无自动备份**：打包下载兜底。
- **协作上传的越权面变大**：P5 重点联调 RLS（用两个测试账号互相攻击式验证）。
- **范围膨胀**：v3 功能多，严格按 P1→P7 顺序交付，每阶段单独验收，不跳步。

## 10. 决定记录

**用户拍板**：命名 Locket；Vite+React+TS+Tailwind；shadcn MCP；Netlify 手动部署接受国内访问风险；
账户体系 + 单向关注授权；邮箱+密码；上传即压缩不保留原图；时间轴/瀑布流/灯箱/心形模式/年度回顾全要；
自定义命名相册分类；协作上传（per-相册开关）；PWA。

**实现者的决定**（如有异议请提出）：关注可见性取单向（A 申请 B 同意 → A 看 B）；协作上传允许任一方向的 accepted 关注者；
3D 墙用 CSS 3D 不用 Three.js；Supabase 优先于 R2；npm；整相册级可见，不做照片级权限。
