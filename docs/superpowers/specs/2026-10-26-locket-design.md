# Locket 设计文档 v2

> 一个照片展示网站：3D 旋转照片墙 + 手机直传照片 + 一键导出画面发朋友圈。
> 多用户：每个人注册后拥有自己的照片墙，可授权互相关注看对方的墙（只读）。
> 整理日期：2026-10-26（v2：按用户拍板升级为账户体系）。状态：待批准。

## 1. 意图与动机

普通相册/网盘缺少「心意感」。Locket（吊坠盒）把照片放进一个 3D 旋转墙里——像把照片装进首饰盒。
首版场景：情侣各自注册，传自己的照片，互相授权后看对方的墙，遇到好看的画面一键导出发朋友圈。
架构上天然多用户，「给谁用」不限于一个人。

**为什么做这个**：仪式感 + 实用（朋友圈素材）+ 练手极致前端动效。

## 2. 目标（首版必须做到）

1. **3D 旋转照片墙**：照片沿圆柱面排布，拖拽旋转（带惯性）、闲置自动慢转；手机触屏可玩。
2. **账户体系**：邮箱注册/登录；每人一面自己的墙。
3. **方便上传**：手机浏览器登录后即可上传，无需装 App。
4. **互相关注/授权**：A 申请关注 B，B 同意后 A 可**只读**看 B 的墙；上传/删除/排序只有墙主能做。
5. **照片管理**：删除照片；长按拖拽调整照片在墙上的顺序（墙主）。
6. **导出画面**：一键把当前墙画面导出 PNG 下载（适合发朋友圈）。
7. **打包下载**：一键把墙里全部照片打包 zip 下载（数据兜底）。
8. **极致动效**：React Bits 组件做氛围（背景、入场、微交互），不是简陋 demo。

## 3. 非目标（首版明确不做）

- 评论、点赞、访客统计
- 照片滤镜/编辑/裁剪（仅上传前压缩）
- 微信小程序、原生 App
- 关注关系的精细化权限（如「部分相册可见」）——关注即整墙可见
- 消息通知（关注申请靠对方登录后看到红点）

## 4. 反目标（即使技术上能跑，出现就算失败）

- **照片丢失**：存储方案必须可靠；打包下载兜底必须真的能用。
- **手机卡顿发烫**：动效必须有移动端降级（`prefers-reduced-motion`、低端机降背景）。
- **国内打不开/传不动**：Netlify 免费托管国内访问一般——用户已知情并接受（有自定义域名空间，后续可切）。
- **越权**：绝不能看到/动到未授权用户的照片（RLS 必须兜死，不能只靠前端隐藏）。

## 5. 约束

- **免费优先**：Netlify 免费静态托管 + Supabase 免费额度（Auth 5万MAU / Storage 1GB / DB 500MB）。
- **技术栈**：Vite + React + TypeScript + Tailwind CSS。
- **组件来源**：React Bits（shadcn 式源码组件，MIT + Commons Clause，个人项目免费可用）。
- **包管理**：npm（E 盘 exFAT 不支持符号链接，pnpm 会挂）。
- **网络**：GitHub 走 SSH；reactbits.dev 拉不动就官网手动复制组件源码。
- **MCP**：`.kimi-code/mcp.json` 已配 shadcn MCP；context7 查文档。
- **部署**：Netlify 手动部署（git 集成或 CLI 由实现时定）。

## 6. 架构

```
┌──────────────────────────────────────────────┐
│  Netlify（静态托管，手动部署）                    │
│  ┌────────────────────────────────────────┐  │
│  │ React SPA (Vite + TS + Tailwind)        │  │
│  │  ├─ 登录/注册页                          │  │
│  │  ├─ 3D 照片墙（CSS 3D transforms）        │  │
│  │  ├─ 关注/授权管理                        │  │
│  │  ├─ 上传（压缩→直传 Storage）             │  │
│  │  ├─ 导出 PNG / 打包下载 zip              │  │
│  │  └─ React Bits 氛围组件                  │  │
│  └────────────────────────────────────────┘  │
└──────┬───────────────────────┬───────────────┘
       │ 用户 JWT (Supabase Auth) │
       ▼                        ▼
  Supabase Auth            Supabase Postgres + Storage
  (邮箱+密码)               photos 表 / follows 表 / Storage 桶
```

### 数据模型（Supabase Postgres）

- `auth.users`：Supabase Auth 自带。
- `photos`：`id`, `owner_id`(→auth.users), `storage_path`, `sort_order`, `created_at`。
- `follows`：`id`, `follower_id`, `followee_id`, `status`('pending'/'accepted'), `created_at`。
  - 唯一约束 `(follower_id, followee_id)`；关注即申请，对方同意后变 accepted。

### 权限（RLS 策略，兜死在数据库层）

- `photos`：SELECT 允许 owner 本人 + 与 owner 存在 `accepted` follow 关系（双向任一方向？——实现者的决定：**任一方向 accepted 即可看**，即互关授权，申请方可看被申请方的墙）。
  > 注：这里取「单向 accepted 即可看」更简单（A 申请→B 同意→A 看 B）。待实现时与用户确认，默认单向。
- `photos`：INSERT/UPDATE/DELETE 仅 owner。
- `follows`：INSERT 任何登录用户（发起申请）；SELECT 仅涉及双方；UPDATE 仅 followee（同意/拒绝）；DELETE 双方。

### 认证方式

- 邮箱 + 密码注册/登录（实现者的决定：避开免费版邮件送达率问题，magic link 留作后续可选项）。

### 3D 墙与导出

- 墙本体：CSS 3D transforms 圆柱排布 + pointer events 拖拽 + 惯性 + 自动旋转（不用 Three.js 做本体，WebGL 只留给背景组件且懒加载）。
- 导出 PNG：`html-to-image` 截当前墙 DOM；若 `preserve-3d` 截图翻车，退化为 canvas 按当前角度重绘（P3 先 spike 验证）。
- 打包下载：前端流式打包 zip（jszip），逐张拉取，带进度条。

## 7. 页面结构

1. **登录/注册页**：邮箱+密码；React Bits 入场动画。
2. **我的墙（首页）**：3D 旋转墙 + 动态背景；浮动 Dock：上传、导出 PNG、打包下载、自动旋转开关、排序模式（墙主）、删除模式。
3. **关注页**：发起关注（输对方邮箱）、待处理申请（同意/拒绝）、我正在看谁的墙。
4. **TA 的墙**：只读视图，同样 3D 可玩，Dock 只有导出/打包下载。

## 8. 阶段拆分

| 阶段 | 内容 | 验收 |
|---|---|---|
| P1 | 脚手架 + 3D 墙空转 + 本地假数据 + React Bits 背景氛围 | 本地能拖能转 |
| P2 | Supabase 项目 + Auth + 我的墙（上传/列表/删除）+ 前端压缩 | 注册登录后手机能传能看能删 |
| P3 | 导出 PNG（含 spike 验证截图方案）+ 打包下载 zip | 导出图能发朋友圈；zip 能完整拉下所有照片 |
| P4 | 关注/授权 + 看 TA 的墙 + 拖拽排序 | A 申请 B 同意，A 能看 B 的墙；墙主能排序 |
| P5 | Netlify 部署 + 移动端降级 + `prefers-reduced-motion` + 额度/错误提示打磨 | 公网全流程走通 |

## 9. 主要风险与对策

- **html-to-image 对 CSS 3D 的兼容性**：P3 最先 spike；翻车就 canvas 重绘。
- **Netlify 国内访问**：用户已接受；后续可绑自定义域名或迁 Cloudflare Pages + 备案域名。
- **免费额度**：照片压缩（长边 2048、WebP，约 300KB/张）后 1GB ≈ 3000 张；页面做额度/错误提示。
- **原图不保留**：上传即压缩，不可逆——已确认接受。
- **Supabase 免费版无自动备份**：打包下载功能即兜底。
- **关注模型的方向性**：默认单向（A 申请 B 同意 → A 看 B）；实现前再与用户确认一次。

## 10. 决定记录

**用户拍板**：命名 Locket；Vite+React+TS+Tailwind；shadcn MCP；账户体系（每人自己的墙）；互相关注/授权看墙；删除+拖拽排序都做；打包下载要；Netlify 手动部署接受国内访问风险。

**实现者的决定**（如有异议请提出）：邮箱+密码认证（不用 magic link）；3D 墙用 CSS 3D；Supabase 优先于 R2；npm；单向关注授权；上传即压缩不保留原图。
